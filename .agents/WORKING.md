# Working

## Bounded work

Size the work to the question: a question gets an answer, not a campaign.
Every batch of work names its owners or files, its budget and the check that
ends it before it starts. Shared headers, registers, manifests and staging
change in one place at a time, never from overlapping edits. Do not build a
work-tracking framework, claim database, template-pack system or scoreboard
service.

Keep a batch's inputs in files it reads, and its scratch under `out/`. Remove
each worktree and branch as its work lands; `main` is the only branch left
behind.

## Keep what a batch found

Write each result to a durable place as it is found: owner, extent, candidate
path and score. Work can stop at any moment (a deadline, a usage limit, a
decision), and temporary directories can be wiped; a stopped batch must leave
its exact candidates recoverable, not only in a final report it never wrote.

## Waves

A time-boxed wave ends with starting and ending exact-C bytes, newly resolved
bytes, adopted owners, parked residual classes, elapsed time and validation
actually run. Measure verified new C per hour and DONE separately. Zero
adoption is a negative result, not permission for a larger identical wave.

At a timed deadline, stop starting searches, finish or revert experiments,
verify accepted work and report the actual result.

## Authority

Only Pascal authorizes compiler, route and hash changes
([COMPILER](COMPILER.md)), new DONE standards ([COMPLETION](COMPLETION.md)),
raising the tooling ceiling ([TOOLING](TOOLING.md)), pushing
([BUILD](BUILD.md)), and rewriting published history. Preserve unrelated work:
no resets to make a gate pass.
